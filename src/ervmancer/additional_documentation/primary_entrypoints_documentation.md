# This is a file to outline the 2 primary entrypoints and their use cases.

# Explanation of commands


  -h, --help            show this help message and exit
  --kd KMER_DICT, --kmer_dict KMER_DICT
                        Absolute path to the kmer dictionary file downloaded from Zenodo
                        (clean_kmer_31_60_percent_cutoff.pkl).
  --b B, --bt2 B        User provided absolute path to self provided bowtie2 SAM
                        alignment file, used for Entrypoint 2.
  --advanced ADVANCED   User provided absolute path to CSV file with user-
                        provided read counts from other methods (see advanced methods)
  --r1 R1               Absolute path to paired-end R1 fastq file for entrypoint 1. This file is
                        also needed for normalization for entrypoint 2, and can be either single strand or paired end for entrypoint 2.
  --r2 R2               Absolute path to paired-end R2 fastq file for entrypoint 1.
  --s1 S1               Absolute path to single strand S1 fastq file for entrypoint 1.
  --keep_files          Keeps intermediate outputs from Samtools, Bedtools, and Bowtie2 (use this to keep SAM files).
  --num_cores NUM_CORES
                        Number of CPU cores used for the bowtie2 processing step. Only used in entrypoint 1.
  --output_dir OUTPUT_DIR
                        Absolute path to base output directory for CSV output
                        and intermediate files. (Output folders are
                        autogenerated if they do not exist already!)
  --bowtie_index BOWTIE_INDEX
                        Absolute path to the Bowtie2 index to be used for
                        processing (from Zenodo or provided by user).

# Example Entrypoint 1: Starting from a fastq file

This entrypoint is used to run ervmancer on single or paired end read fastq files. 
The files are aligned using Bowtie2 and mapped to the phylogenetic tree.

Output is four CSV files corresponding to HERV counts normalized without summing counts under each clade,
HERV counts without normalization and without summing counts under each clade,
HERV counts with normalization with all counts beneath the clade summed into each clade,
and HERV counts without normalization with all counts beneath the clade summed into each clade.

Example run for entrypoint 1:

conda activate <your_ervmancer_env>

ervmancer --r1 PATH_TO_R1 \
    --r2 PATH_TO_R2 \
    --kd path_to_zenodo_download/clean_kmer_31_60_percent_cutoff.pkl \
    --keep_files \ # used to keep intermediate files.
    --output_dir YOUR_OUTPUT_DIRECTORY \
    --bowtie_index PATH_TO_BT2_INDEX/GRCh38_noalt_as \
    --num_cores 8 # number of cores for Bowtie2 to run

# Example Entrypoint 2

This entrypoint can be used with a SAM file. The envisioned use case for this entrypoint is if the end user wishes to run ERVmancer again without rerunning bowtie2, or if the end user wishes to use their own bowtie2 parameters before mapping to the phylogenetic tree.

Output is the same as entrypoint 1.

conda activate <your_ervmancer_env>

ervmancer --r1 PATH_TO_R1 \ # required for normalization, if single stranded just provide the single strand file using --r1.
    -b YOUR_MULTIMAPPED_SAM_FILE \
    --kd path_to_zenodo_download/clean_kmer_31_60_percent_cutoff.pkl \
    --keep_files \ # used to keep intermediate files. Otherwise, ALL files in the intermediate folder will be deleted.
    --output_dir YOUR_OUTPUT_DIRECTORY \
